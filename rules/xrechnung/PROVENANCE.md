# XRechnung 3.0 CIUS (CII)

Source: [KoSIT validator configuration v2026-08-31](https://github.com/itplr-kosit/validator-configuration-xrechnung/releases/tag/v2026-08-31).
Archive: `xrechnung-3.0.2-validator-configuration-2026-08-31.zip`, published September 2, 2026.
SHA-256: `2530cd107c414511c5d0462ec10f886910395abfca820db82e83d70bf01221a8` (GitHub release asset digest).

Only the CIUS CII scenario is implemented. The original `scenarios.xml` is retained
as evidence; its other scenarios are not enabled. CII schema D16B, CEN Schematron
1.3.16, XRechnung Schematron 2.6.0 for specification 3.0.2. Identifier suffix 3.0
is the official identifier; 3.0.2 is not a separate identifier.

Files copied byte-for-byte into `source/`:

- `resources/cii/16b/xsd/*.xsd` (four UN/CEFACT schemas).
- `resources/cii/16b/xsl/EN16931-CII-validation.xsl`.
- `resources/xrechnung/3.0.2/xsl/XRechnung-CII-validation.xsl`.
- `scenarios.xml` from the archive root.

`source-lock.json` pins their hashes and the unchanged SaxonJS browser runtime.
`schemas.json` embeds the schema texts. `cen.sef.json` and `xrechnung.sef.json`
are generated by xslt3 2.7.0 from the original XSLT with a virtual XML base.
The compiler copy alone changes the integral digit-string cast in `xr:checkIBAN`
from `xs:integer` to `xs:decimal`: SaxonJS 2.7 integer arithmetic otherwise loses
precision on the large integer before `mod 97`. Decimal arithmetic preserves
the integer value and modulo result. The original files and SVRL predicates remain
unchanged. The build guards this single replacement; manifest and reports disclose it.
No invoice rule is removed or weakened. KoSIT comparisons include valid and invalid
German, British and Maltese example IBANs, including spaces and long digit strings.

Severity overrides are taken exactly from `EN16931 XRechnung (CII)` in the pinned
configuration. Build-time checks bind the registry's identifier, both XSLT stages
and overrides to that original scenario. Notably CII-SR-465/466 become errors,
and CII-SR-475/476 become information, as KoSIT replaces their incorrect contexts
with BR-TMP-4/5. All overrides and original flags are disclosed in results.

`reference-lock.json` pins optional KoSIT 1.6.3 development assets, including the
report stylesheets used for acceptance. JARs, archive and extracted configuration
are ignored. Neither Java nor KoSIT runs in the application or normal build/tests.
